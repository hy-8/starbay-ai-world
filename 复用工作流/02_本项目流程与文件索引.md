# 星湾实际制作流程与文件索引

记录日期：2026-09-13。路径以仓库根目录为基准；活动游戏在 `星湾街区_3D探索`，交付在 `星湾发布`。历史版本文件夹仅作本地备份。

## 已完成的路线

参考场景 → 人工确定布局与程序化 Blender 建模 → GLB 与空间元数据 → Three.js 可探索游戏 → 规则行为与本地 Qwen 意图 → 实机验证 → 固定步长录制 → 本地 OpenChatCut 剪辑 → 中文旁白、说明文档、概念封面 → GitHub 与 Release。

这次不是摄影测量，也不是用户上传一张图后自动重建整个可玩世界。模型和场景主要由制作脚本构造，再由游戏代码补齐运行系统。

Blender 安装在制作机 D 盘。模型重建顺序如下，仅对已保护手工编辑的工作副本执行：

```powershell
# 当前工作目录须为游戏目录；替换成该机器的 Blender 路径。
& 'D:\tools\Blender\blender-4.5.9-windows-x64\blender.exe' --background --python build_people_v4.py
& 'D:\tools\Blender\blender-4.5.9-windows-x64\blender.exe' --background --python build_scene.py -- --skip-preview
```

脚本会重建并覆盖相关输出。手工改过 .blend 时，应从编辑后的工程单独导出所需 GLB，并同步相应元数据；不能靠重跑旧生成脚本保存手工改动。

## AI 到 NPC 的实际链路

1. 浏览器把玩家消息、角色状态与有限上下文交给本地服务。
2. `server.py` 请求 Ollama，默认模型 `qwen3.5:4b`，也可由 `STARBAY_AI_MODEL` 指定。
3. 模型返回 `say`、`destination`、`reason`。服务校验允许目的地；儿童使用更小的活动范围，明确的玩家目的地还会由规则解析校正。
4. 浏览器执行目标、寻路和带路等待；`people.js` 根据实际移动距离生成步态。
5. AI 不可用时，探索与规则系统继续运行。当前任务为规则生成，不是 Qwen 临时编写。

当前有四类外观、12 位运行居民、12 个探索地点、8 类委托与约 20 分钟一天的昼夜循环。商店不少陈设仍以视觉探索为主，街区币目前主要为奖励记录。

| 路径（相对于星湾发布） | 内容 |
|---|---|

| `中文旁白脚本.md` | 六句旁白与镜头安排 |
| `星湾街区_AI宣传片_中文旁白版_1080p.mp4` | 64 秒、1080p、30 fps 中文旁白成片 |
| `工程/星湾街区_中文旁白版_可编辑工程.ccproj` | 包含素材的本地 OpenChatCut 工程 |
| `制作/build_document.py` | 玩法与技术说明生成脚本 |
| `星湾街区生活_玩法与AI技术说明.docx` / `.pdf` | 七页说明 |
| `封面/` | 4:3、3:4 概念封面及生成提示词 |

主剪辑使用本地 OpenChatCut。九段实机画面上叠加可编辑动效，另有音乐和六段旁白。旁白使用 MiniMax `male-qn-jingying`，模型 `speech-2.8-hd`，分段生成，音乐有独立音量关键帧。复用时重新发现工具、项目与时间线，不照搬旧会话 ID。

卡顿修订的关键是固定模拟步长采集，而不是单纯增加导出帧率。已验证成片规格与旁白混入；自动冻结提示中的静态夜景、等待和任务阅读镜头需要结合画面判断。

复用本地 OpenChatCut 接口时，导入素材或修改工程可能使旧编辑上下文失效，应获取新会话/编辑草案，再应用新修改。交付 .ccproj 需确认包含素材并可解析；发布副本去除工具聊天和会话记录时，要保留时间线与所有媒体字节，并验证引用和校验和。

## 优先改进建议

1. 建立导出清单和版本校验，让 Blender 改动、GLB、碰撞和导航同步，避免只更新画面。
2. 固定机位与时间制作 Blender/游戏对照图，统一材质、曝光和主光方向。
3. 升级 NPC 面部、蒙皮骨骼、转身和动作混合；保留碰撞、落脚与导航的确定性控制。
4. 给 AI 增加受控记忆和可解释的状态反馈，再逐步试验有校验的动态任务。
5. 将场景上传另立为产品模块：素材解析、布局确认、重建、碰撞导航生成与人工校验分步验收，先支持少量受控场景类型。
