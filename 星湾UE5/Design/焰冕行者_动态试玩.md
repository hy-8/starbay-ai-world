# 焰冕行者 · 原生动态角色候选 v0.4.0

本版把红金礼服角色从 Blender 静态展示推进到 UE5.6 的原生第三人称角色。它是可继续制作的游戏原型；面部、发型、服装受力和技能表现还没有达到用户参考中的商业 MMO 珍品皮肤质量。

## 试玩

Windows 包解压后双击 `焰冕试炼.cmd`。`焰冕游览星湾.cmd` 使用同一角色进入原街区；原地图自身的默认角色保持原设置。

| 操作 | 行为 |
|---|---|
| WASD / 方向键 | 普通移动，直线目标速度 3 米/秒 |
| Shift + 移动 | 冲刺，速度上限 6 米/秒 |
| 鼠标 | 第三人称视角 |
| 空格 | 起跳，随后进入下落和落地动画 |
| Q / 鼠标左键 | 约 4 秒的抬手、释放、收势动作；动画通知在手部生成火星 |
| Alt + F4 | 退出独立程序 |

普通移动在斜向组合输入时会更快，当前尚未加入统一的斜向步行速度归一化。鼠标右键的旧模板蓄力映射已移除，避免触发未完成的组合技能。

## 已验证的实现

- 骨骼模型、七个独立动画（待机、走、跑、跳、下落、落地、施法）和 UE 动画蓝图。
- UE 编辑器真实 PIE 中通过 Enhanced Input 开发命令走完整个按键映射链：直线走路 300 cm/s、冲刺 600 cm/s、起跳约 127 cm；施法结束后恢复，第二次施法能重新触发。这是原生输入映射测试，**不是物理键盘人工验收**。
- 最终材质和火星在真实 UE 画面中检查；预览不是 AI 合成图。Windows 打包与独立进程验证结果另见 `Validation/ember_delivery.json`。
- LOD0/1/2 分别为 527,837 / 146,241 / 77,689 个 UE 渲染顶点。它们受 UV、法线和材质边界拆分影响，不能直接与 Blender 顶点数相等比较。

## 资产与驱动链

`v14 静态设计 → rig04 骨骼/蒙皮 → motion05 动作 → UE Ember_v04 → 原生 Windows 包`。

Blender 保留 Epic Manny 的参考骨架静止姿态，添加披风、长发、裙摆及手指骨骼。手指使用明确 CC0 的 MakeHuman 关节与权重来源，避免早期最近邻蒙皮造成手腕拉伸；左手持杖姿态仍需精修。

走、跑、跳及落地从本机合法安装的 Epic 模板动作转换，服饰辅助骨骼追加烘焙运动。施法为原创关键帧动作，不是动作捕捉。UE 中由 CharacterMovement 驱动物理移动，由速度混合空间和动画状态机选择动作，由 Montage 播放施法。

角色蓝图组合官方第三人称与战斗模板。父、子蓝图若绑定同一移动 Input Action，会叠加输入；本版在一次性隔离工程中将父蓝图移动引用替换成独立的 `IA_EmberSprintMove`，再只回传该蓝图与动作资产。正式工程不执行资产合并删除。普通移动由子蓝图接收，冲刺使用 Shift 组合触发。

火星由 Niagara 生成，五个动画通知负责蓄势和释放时机。粒子模拟基于 Epic 示例，火焰 Sprite 材质为本项目程序着色器。独立包运行这些功能不需要 Python、Blender 或本地大模型。试炼场包含程序熔岩、岩台、柱子和固定曝光灯光。

## 仍待实现或精修

1. 面部皮肤贴图、眼睑/嘴角精雕、表情骨骼与更自然的发际线；目前脸部仍有明显模型感。
2. 裁片式服装、真实重力褶皱与 Chaos Cloth。现有披风/头发/裙摆是**烘焙骨骼动画**，不具备碰撞感知；某些动作仍可能穿模。
3. 继续降低头发和饰件面数，改善握杖和脚部轮廓，逐镜检查滑步、落地衔接及镜头遮挡。
4. 原生地面法阵、技能轨迹、伤害判定、音效和镜头反馈。当前交付的是动作加火星；测试用的 MPC 法阵尚未接入 Q 的原生触发，不能当作已交付技能。服装按施法曲线蓄能发光也尚未完成。
5. NPC、Qwen、委托、昼夜和存档迁移。**本角色当前不是 AI 驱动的 NPC**；原浏览器版 Qwen 只负责语言理解和高层目的地决策，导航与动画仍由游戏系统执行。

“任意图片自动生成高质量可玩世界”、完整开放世界及参考级商业画质均不属于本版已完成功能。

## 继续开发

UE 地图：`/Game/Starbay/Ember_v04/L_EmberArena`；最终玩家：`BP_EmberHero`。源工程内打开 `.uproject`，加载该地图并 Play。不要重新运行首次场景导入。

角色 Blender 工程为 `角色工坊/焰冕行者/Exports/motion05/Ember_Animated.blend`；不同动作保存在 Actions 中。`rig04` 为绑定基础，`v14` 为静态设计来源。新修改另存新候选，保留旧版本。

发行源包通过 Asset Registry 收集两个地图的实际依赖。保留一份历史路径下的共享织锦贴图，不包含被淘汰的角色模型；官方模板的五条编辑用途软引用在安装资源中不存在，收集报告单列记录，不伪造文件补齐。最终 cook 结果以实际报告为准。
